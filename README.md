# 📖 Предыстория

Впервые эта игра появилась в 2025 году как обычный университетский проект трёх студентов. Сначала была создана версия на Java для одной дисциплины, а затем игра была перенесена на **Clickteam Fusion 2.5** для другой.

Меня часто посещала мысль:
> **"Эх, вот бы сделать чисто для себя какую-нибудь программку или игру на айфон. Но я не хочу для этого покупать Mac или арендовать облачный."**

И вот однажды, копавшись в публичных репозиториях GitHub и в очередной раз спрашивая ChatGPT, могу ли я без Mac собрать приложение для своего айфона, я узнал, что такая возможность есть и это абсолютно бесплатно и в какой-то степени безлимитно!

После десятков ~сообщений ChatGPT~ неудачных сборок, небольшого изучения устройства Xcode-проектов и GitHub Actions, а также особенностей сборки iOS-приложений у меня получилось настроить полностью автоматическую сборку неподписанного .ipa прямо на GitHub.

Возможно, этот репозиторий вдохновит тебя на создание чего-нибудь своего)

> [!TIP]
> Если тебе интересна не столько сама игра, сколько процесс сборки iOS-приложения без Mac, можешь сразу перейти к разделу **⚙️ Техническая часть**.

# 🎮 Об игре

**«Смешарио»** - это небольшой бесконечный автораннер.

Игрок выбирает одного из 4 персонажей и его цель - пробежать как можно дальше, перепрыгивая препятствия и собирая предметы. Чем дальше получится забраться и чем больше предметов будет собрано, тем больше очков можно заработать и тем больше персонажей открыть.

Каждый герой пришёл в огород Копатыча со своей целью:

- 🥕 **Крош** собирает морковь
- 🌵 **Ёжик** - кактусы
- 📜 **Бараш** - потерянные листы со своими стихами
- 🍬 **Нюша** - конфеты

У каждого персонажа есть уникальная фраза, рассказывающая о том, зачем он бегает по огороду. Фразы были озвучены нами, а затем голос был изменён с помощью нейросети. Голосовые модели персонажей были взяты из публичного доступа.

> [!IMPORTANT]
> Игра представляет из себя **демо-версию** с возможными багами, а также с неполным выбором персонажей (доступны только Крош и Ёжик).

# ⚙️ Техническая часть

Самой интересной частью проекта оказалась вовсе не игра, а процесс её переноса на iOS.

Проект разрабатывался в **Clickteam Fusion 2.5+ Developer** и экспортировался в Xcode-проект. На этом этапе обычно предполагается, что дальнейшая работа будет происходить на Mac с установленным Xcode.

Но мне хотелось проверить, можно ли обойтись совсем без собственного компьютера Apple.

Ответ — **да.**

После нескольких дней экспериментов удалось добиться полностью автоматической сборки приложения средствами **GitHub Actions**, используя виртуальную машину macOS с предустановленным Xcode.

---

## 🔄 Схема сборки

```text
Clickteam Fusion
        │
        ▼
Экспорт Xcode-проекта
        │
        ▼
     GitHub
        │
        ▼
 GitHub Actions
(macOS + Xcode)
        │
        ▼
   xcodebuild
        │
        ▼
Неподписанный IPA
        │
        ▼
SideStore / AltStore
        │
        ▼
      📱 iPhone
```

---

## 🛠 Что происходит автоматически

После загрузки проекта в GitHub достаточно запустить Workflow.

Далее GitHub самостоятельно:

- 📥 получает исходный код репозитория;
- 🍎 запускает виртуальную машину с macOS и Xcode;
- 🔨 собирает Xcode-проект через `xcodebuild`;
- 📦 упаковывает приложение в **IPA**;
- ☁️ прикрепляет готовый файл к артефактам сборки.

Весь процесс полностью автоматизирован и не требует ручного запуска Xcode.

---

## 🚧 С какими проблемами пришлось столкнуться

На пути к первой успешной сборке встретилось несколько неожиданных препятствий.

### 🔹 Xcode Package Plugins

Современные версии Xcode блокируют выполнение некоторых Package Plugins в среде CI.

Для автоматической сборки пришлось явно отключить их проверку:

```bash
defaults write com.apple.dt.Xcode IDESkipPackagePluginFingerprintValidatation -bool YES
defaults write com.apple.dt.Xcode IDESkipMacroFingerprintValidation -bool YES
```

---

### 🔹 Box2D

Во время первой сборки линковщик сообщал:

```text
ld: library 'Box2D' not found
```

Хотя сама библиотека успешно компилировалась.

Причиной оказался порядок сборки целей проекта. После небольшой корректировки Workflow библиотека начала собираться раньше основного приложения, и проблема исчезла.

---

### 🔹 Подпись приложения

Поскольку сборка предназначена для личного использования, IPA создаётся **без цифровой подписи**.

Подпись выполняется уже после сборки с помощью SideStore, AltStore или другого совместимого инструмента.
